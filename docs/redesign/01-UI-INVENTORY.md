# UI Inventory

Inventaris ini mencatat seluruh layar yang benar-benar aktif pada routing/controller saat baseline dibekukan. View yang ada di filesystem tetapi tidak dapat dirender oleh alur controller aktif dipisahkan sebagai dormant/legacy dan **bukan** layar redesign.

## Ringkasan dan aturan hitung

- **23 layar aktif** (`UI-001` sampai `UI-023`).
- **15 primary screen variants** yang berbeda secara struktur/data projection: 6 dashboard, 3 daftar tiket, dan 6 detail tiket.
- Variant multi-role tidak dihitung secara kombinatorial; ia merupakan komposisi branch aktual dengan override Ketua Tim Kerja dan current-approver check.
- GET alias yang merender layar yang sama tidak dihitung sebagai layar tambahan.
- Redirect, JSON health response, image response, file download, dan PDF export template dicatat sebagai active non-screen responses.
- Semua layar utama selain login/change-password/403 memakai `layouts.app`. Login dan change-password memakai `layouts.guest`; 403 adalah document standalone.

## Layout dan behavior global

| Layout | Pengguna | Contract penting |
|---|---|---|
| `resources/views/layouts/app.blade.php` | Seluruh screen authenticated selain change-password | CSRF meta; Vite asset; Livewire styles/scripts dan navigation hook; sidebar desktop; menu mobile; role/policy-aware navigation; notification dropdown; password link; logout POST; flash include; global loading overlay; branding data. |
| `resources/views/layouts/guest.blade.php` | Login dan change-password | Vite asset; branding; flash; global loading overlay; guest card. Change-password tetap berada di authenticated route walau memakai guest layout. |
| Standalone `resources/views/errors/403.blade.php` | Authorization failure | Vite asset dan branding; kembali ke dashboard bila authenticated atau login bila guest. |

Behavior global `resources/js/app.js`: SweetAlert flash/confirmation, global submit/navigation loading, Livewire navigation re-initialization, sidebar state di `localStorage`, menu/disclosure, generic modal focus trap/restore/close/reset, serta handler khusus per screen. Tidak ada client-side router atau client-side state store.

## E. Endpoint aktif tanpa trigger UI aktif yang ditemukan

Endpoint berikut tetap bagian routing/backend contract, tetapi redesign tidak boleh menciptakan control baru untuknya tanpa keputusan produk terpisah:

- `tickets.claim` dan `tickets.handle`;
- room create/update/status (`admin.catalog.rooms.*`);
- attachment-policy create/update/status (`admin.catalog.attachment-policies.*`);
- operational policy calendar/settings/approver update (`admin.operational-policies.*`);
- service field status (`admin.catalog.fields.status`); trigger Blade yang ditemukan hanya berada pada dormant catalog modal;
- split user role/team/skill endpoints (`admin.users.roles.update`, `admin.users.team.update`, `admin.users.team.remove`, `admin.users.skills.update`) karena form aktif utama menyimpan komposisi melalui user create/update;
- setiap team status/delete action yang route-nya ada tetapi control aktifnya perlu diverifikasi per record state sebelum dibuat ulang.

Tidak adanya trigger UI bukan izin untuk menghapus endpoint, mengubahnya, atau mengaktifkannya melalui redesign.
