# Design Open Questions

Register ini menyimpan keputusan visual atau interaction yang belum mempunyai evidence cukup pada FASE 3.2. Item yang memerlukan screenshot tidak dijawab dengan tebakan. Tidak ada item di sini yang memberi izin implementation, defect repair, feature expansion, atau perubahan contract.

## Decision Stage Definitions

| Decision stage | Meaning |
|---|---|
| `CAN DECIDE BEFORE SCREENSHOT` | Evidence source/contract cukup untuk membuat explicit design/interaction decision, tetapi keputusan belum disetujui dan tetap membutuhkan acceptance criteria. |
| `MUST WAIT FOR MANUAL BASELINE` | Existing pixel, responsive, focus, overflow, atau density evidence diperlukan sebelum memilih direction exact. |
| `MUST WAIT FOR DESIGN SYSTEM PHASE` | Direction relatif sudah cukup; exact token/system choice memang merupakan scope FASE 3.3 dan tidak diputuskan sekarang. |

## Resolution Rules

1. An open question may be closed only with a recorded decision, evidence reference, affected SIG/UI/variant list, and regression/acceptance impact.
2. A screenshot-dependent question cannot be closed from source inspection or Frappe reference alone.
3. Exact token questions are deferred to FASE 3.3 and must not be smuggled into FASE 3.2 examples.
4. OPEN-021 and OPEN-022 are explicit interaction decisions; neither is automatically approved because it appears beneficial.
5. Resolving a question cannot alter frozen route, form, query, policy, projection, workflow, modal, error, or role behavior.
6. Any evidence that reveals an existing defect is classified separately under the VIS/future-change rules before a design decision is made.

These 23 questions do not block the qualitative north star or UI grammar. They intentionally prevent premature exact tokens, dimensions, and interaction changes while manual visual baseline remains unavailable.
